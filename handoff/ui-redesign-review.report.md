# UI redesign review (task 5.1), read-only

Checks run in ui/: vitest 52 files / 783 tests pass; `tsc -p tsconfig.app.json --noEmit` clean; `oxlint --deny-warnings src` clean (no output). Prettier and the image script were not part of this review.

## High

1. **CV preview iframe renders unstyled under the production CSP.** ui/src/export/ExportPage.tsx:307-312 (`srcDoc` + `sandbox=""`). An `srcdoc` document inherits the embedder's CSP, so nginx's `style-src 'self'` (ui/nginx/security-headers.conf:3) is intersected with the backend page's own meta CSP (`style-src 'unsafe-inline'`, backend/.../export/internal/HtmlRenderer.kt:31). The `<style>` block emitted at HtmlRenderer.kt:33 is blocked, so the preview shows plain unstyled HTML (images from `data:` still load). Tests (jsdom) cannot see this. The iframe is sandboxed with an empty token list (no scripts, no same-origin), which is correct and should stay.
   Fix options: (a) serve the preview from a backend URL (`src=` to an authenticated endpoint is awkward with bearer tokens, so use a blob URL: `URL.createObjectURL(new Blob([html], {type:'text/html'}))`; a blob: iframe also inherits CSP in Chromium, so this alone does not help); (b) practical fix: add a nonce-free hash is impossible per template, so either send `style-src 'self' 'unsafe-inline'` only on a dedicated `/preview` nginx location that serves a static shell page, or (c) render the preview into a `<img>`/PDF via the existing PDF endpoint (`<object>`/img-src would need `blob:`). Decide with the CSP owner; verify on s4v3.net (memory: test on prod). Also add a note in the spec, since "CSP-safe" is currently only true for the app itself.

## Medium

   - ui/src/applications/ApplicationPage.tsx:88

   Fix: render `<div className="page"><PageHeader title="<page name>" /><p role="status">Loading…</p></div>` in each (one tiny shared `PageLoading({title})` in ui/ would do). This also avoids layout jump.

4. **ProfilePage and FileCabinet still on legacy markup**: ProfilePage.tsx:275 (`<p role="alert">`), :314 and :335 (`.notice` div/p), :349, :351; files/FileCabinet.tsx:172-177, 260, 291, 306-309 (`<p role="alert|status">`, `.notice`, undefined `.files`/`.file-cabinet` classes: no rule exists in any stylesheet); profile/fields.tsx:17, TagInput.tsx:86, FillFromCv.tsx:34, OpenSourceSection.tsx:188, 220, 287-291 (bare `role="alert"` spans). Use `Alert` (tone danger/info/success) and FormField-style `aria-describedby`/`aria-invalid`; `fields.tsx`/`TagInput.tsx` errors are an announced span but the inputs get no `aria-describedby`/`aria-invalid` (check fields.tsx TextInput/Select/TagInput; the design-system `FormField` does this correctly).
5. **Legacy `index.css` still carries rules that duplicate or shadow components.css**: `textarea, select` block (index.css:36-47) duplicates `input/select/textarea` in components.css:~117 with different radius (0.4rem vs token) and padding; `.tag-list li/button` (index.css:84-106) duplicate components.css:728-745 (the raw `0.4rem`, `1rem`, `0.15rem` values bypass tokens, and `form input {display:block;width:100%}` leaks into checkboxes/radios until components' more specific rule overrides). `.export-field` (index.css:120-126) is used by no component. `section {margin-bottom:2rem}` (index.css:~116) is a global element rule that also hits Card sections, landing sections and collapsibles. Fix: finish converting ProfilePage/FileCabinet/fields, then delete index.css content except the three `@import`s (and move `.row`, `.actions`, `fieldset` to components.css with tokens). Update components.css:3 comment.
6. **`.row` on phone width** (index.css:61-73, used by profile/fields.tsx:219): `display:flex` with no wrap and `flex:1` labels with `width:100%` inputs plus a button; at 320 px the input is squeezed to roughly 100 px. Add `flex-wrap: wrap` (or stack under 40rem).

Note: a heading inside `summary` has its role overridden by some AT combinations (Safari/VoiceOver announces the button only); acceptable, but verify with VoiceOver on prod. `revealAndFocus` opens ancestors before focusing (good). SkillsSection rows use `fieldset`+`legend` with unique accessible names for remove buttons (good).
