# jobimport

Purpose: import a job from a URL the user pastes.

## Internal (`internal/`)
- `UrlRules`: accepts only https, port 443, no userinfo, a DNS name (no IP literal); builds the canonical URL (lower-case host, no fragment, no `utm_*`/`gclid`/`fbclid`, no trailing slash); refuses linkedin.com and indeed.com and their subdomains.
- `AddressRules`: public-address check (loopback, link-local incl. metadata, private, CGNAT, unique-local, multicast, unspecified, documentation ranges, 6to4, Teredo, `::/96`, IPv4-mapped and NAT64 forms).
- `SafeFetcher`: resolves, requires every address to be public, connects a TLS socket to a validated address (the next validated one when a connect fails) with SNI and certificate check for the name, GET over HTTP/1.1, at most 3 revalidated redirects, 10 s, 1 MB, HTML only. Failures are `FetchError` codes; URLs and content are never logged.
- `JobContactGrounding`: pure function over (draft, page text). Keeps an extracted detail only if the page contains it, else null (never fails the import, never logged): e-mail by pattern and case-insensitive occurrence; phone with at least 7 digits that occur once spaces, dots, dashes, slashes and brackets are ignored; postal code of 4 or 5 digits occurring as its own number; street, city and person when every word is on the page. A value planted in the page passes, so the user reviews every value. The six values are columns on `job_import_draft` (`014-application-contact.sql`) and are personal data of a third party: owner-scoped, removed with the draft, never logged.
- `PageText`: jsoup to plain text, capped at 30 000 characters; under 300 characters is unreadable.

## API (`net.s4v3.backend.jobimport`)
- `JobImportService`: `preview(sub, ImportRequest)` fetches the page (or takes pasted text, no fetch), extracts with `llm.JobExtractor`, checks that at least 80 % of the words of the description, the title and the company occur in the page text, grounds the company address and contact (`JobContactGrounding`), and stores a draft (1 hour, owner-scoped). `confirm(sub, draftId, ImportEdits)` creates only an application of the caller through `ApplicationService.trackImported` (`source = IMPORT`, no posting, never shared, live status OPEN) and deletes the draft; the same canonical link imported again returns the existing application (`created=false`). `ImportPreview.contact` / `ImportEdits.contact` (`ImportContact`: street, postal code, city, person, phone, e-mail) carry the six details; on confirm a null edit keeps the draft's value, a blank one clears it, limits 200/10/200/200/40/254 and an e-mail shape else `invalid_edit`, and they are passed to `trackImported` in `JobData.contact`. `removeUserData(sub)` deletes a user's drafts (no account deletion flow exists yet to call it). Failures are `JobImportException` with a fixed `ImportError` code.
- `JobImportController`: `POST /api/job-imports/preview` and `POST /api/job-imports`; errors are `{error, message}` with the statuses of the job-import spec, `Retry-After` on 429.
- Limits, in memory: per user `jobhunter.import.previews-per-hour` (20) and `confirms-per-day` (10); previews in flight 2 per user (`max-concurrent-previews-per-user`) and 8 in total (`max-concurrent-previews`), answered 429 `rate_limited`; `ImportBodyLimit` refuses import request bodies over 256 KB (413).
- `ImportDrafts` (JDBC, drafts only) and `DraftPurge` (hourly removal of expired drafts) are internal. Nothing is logged but codes, draft ids and durations.
